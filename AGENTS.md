# LoreStitch Agent Orchestrator

LoreStitch is an Angular editor and version control manager for SillyTavern lorebooks and World Info cards.

Directory map: `src/app/core` (models + services, UI-framework-free) · `src/app/features` (per-feature components) · `src/app/shared` (cross-feature components/services) · `src/testing` (shared unit fixtures) · `e2e/` (Playwright specs + `helpers.ts`) · `next_tasks/` (planning + archive) — each directory ships its own README.

## Operating Principles

- **Route Before Acting**: Inspect your assigned task and read the corresponding persona guide in `.zcode/agents/` before modifying code.
- **Strict Invariants**:
  - No `::ng-deep` or legacy CSS overrides.
  - Angular 22 reactivity: use Signals (`signal()`, `computed()`, `input()`, `output()`) over RxJS state.
  - Dual-container panes (dialog on tablet/desktop, bottom sheet on phones) open only through `ResponsiveOverlayService.openResponsive` (`src/app/shared/services/responsive-overlay.service.ts`); viewport branching never appears at call sites.
  - Every book-carrying export validates first via `validateBook` (`core/models/book-schema.ts`) and returns `ExportResult` (`import-export.service.ts`) — never a bare download; clean books must export byte-identically; unknown vendor keys are never dropped on import and never rewritten on export outside a user-consented `planBookRepair` (`core/models/book-repair.ts`) applied through `WorkspaceService.applyBookRepair`.
- **Module Naming**: injectable classes get the `.service.ts` suffix + `@Service()` decorator; pure framework-free analysis code lands as bare-name modules with no decorator, even under `core/services/` (`sha256.ts`, `token-estimator.ts`, `linter.ts`, `entry-memo.ts` precedent). Identity-keyed WeakMap memos ride the immutable-update invariant with a purity doc at the module head (`entry-memo.ts`, linter.ts's pair-verdict memos) — no clear/invalidate API, GC reclaims. App-domain model types (`ProjectWorkspace`, `ProjectCommit`, `LintPrefs`) live in `core/models/project.model.ts`; `lorebook.model.ts` is the SillyTavern vendor contract only — new app-side model code goes to the former, never the vendor file.
- **Workspace Mutations Go Through Service Mutators**: components write project/workspace state only via narrow typed public mutators on `WorkspaceService` (they route through the private `mutateProject` chokepoint → immutable replace → debounced IndexedDB save); never `activeProject.set` from features — a direct write skips persistence.
- **Text Edits Commit on Idle**: `entrySliceSignal` commits text/extension-slice edits on a 300 ms trailing debounce (`EDIT_COMMIT_DEBOUNCE_MS`) — never write per keystroke; the draft flushes on timer, `DestroyRef`, or external replacement. The merge rule is field-granular (one level into plain-object bags): an external write to a slice field wins and reseeds, non-slice external patches re-apply the draft — a sibling `extensions` chip write must never drop a typed group/weight draft. Discrete controls (chips/toggles/selects) stay immediate via `EntryUpdatesService`. Readers of workspace state right after typing (commit, export, delimiter apply) see committed bytes only — type-then-assert e2e flows wait out the window (`EDIT_COMMIT_FLUSH_MS` precedent in round-trip.spec).
- **Lint Cadence**: the topbar badge reads the graph-free pass (`LinterState.entryDiagnostics` → `lintBook(book, { includeGraphRules: false })`) — recursion-cycle/self-trigger findings appear only in the health pane; `lintBook(book)` / `lintBook(book, {})` output is pinned byte-identical. The health pane is async: `LinterState.healthRun` drives the chunked pass engine (`createLintPass`/`lintBookChunked`, pair-verdict memos) with phase-weighted progress and token+project-identity supersession; results render only from the delivered run. Unit specs drive the run through the `HEALTH_RUN_YIELD` InjectionToken seam; e2e pins auto-wait over the loading state.
- **Pipeline Order**: implementation agents first (`core-engine` → `ui-specialist`), then `ts-reviewer` (typing/lint review) **before** `qa-auditor`. QA runs on two tiers — this is a small app and the full E2E matrix is expensive, so E2E is an end-of-branch gate, never a per-phase tax — and the fast gates close **every** phase, run by the orchestrator between dispatches:
  - **Per task (fast gate)**: `qa-auditor` runs build, unit tests + coverage, lint, `typecheck:e2e`, and a `desktop-chrome`-only Playwright smoke of just the specs the task touched or authored. E2E specs are still written and migrated in-task; only the full-matrix execution is deferred.
  - **Branch-final sweep (once per task branch, at its close)**: the full three-project Playwright matrix run per project (`--project=<name>` — see the Playwright notes below), plus a final `npm test --coverage` and `npm run lint`, before pushing the branch for user testing. A red spec loops back to the task that authored it (fix-forward); inside the loop re-run only the failing project/spec, and repeat the whole sweep at the end.
- **Gate Failures Fix Forward**: a red gate means the responsible subagent fixes and re-runs its own phase; the pipeline never advances on a red gate. After two consecutive failed fix attempts, stop and escalate to the user with the failing output.
- **Human Sign-off at Gates**: changes that alter exported bytes, entry `content` output, or behavior pinned by existing tests — and any visual design spec — require a user checkpoint: post the old-vs-new contract with a minimal repro (or the evidence-backed spec), then wait for the explicit answer; an unanswered gate means stop at the gate, never close on a recommended default, and never dispatch the downstream phase unapproved.
- **Visual Feature Baseline**: any task that adds or reshapes UI captures before/after screenshots under the gitignored `__screenshots__/<task>/{before,after}/` (double underscore — gitignored; the `__screenshots__/linter/capture.mjs` precedent), with identical pinned conditions for both sets — same browser, fixed viewports (1280×800 desktop, 1024×768 tablet, 390×844 mobile), one explicit theme (never system), the same seeded project, settled rendering — and posts the side-by-side comparison to the user with the phase report.
- **Design Checkpoint Evidence**: a visual design gate is approved against evidence, not prose alone — every new interactive control in a design spec cites the in-app exemplar it reuses or attaches a rendered mock; prose-only specs hide affordance and state problems.
- **Commit Per Phase**: each phase's deliverable (the subagent's landed work) is an atomic git commit following Conventional Commits 1.0.0 — `<type>(<scope>): <description>` in imperative mood (e.g., `fix(delimiters): detect mismatched whole-content wrappers`); breaking behavior changes carry `!` or a `BREAKING CHANGE:` footer. Full spec and house rules: `.zcode/agents/rules/conventional-commits.md` (always-on).

## Standard Verification Commands

- Dev server: `npm start`
- Build check: `npm run build`
- Unit tests (one-shot): `CI=true npm test -- --watch=false` (plain `npm test` may watch)
- Coverage: `CI=true npm test -- --watch=false --coverage`
- E2E & fidelity: `npx playwright test` (branch-final sweep — run per project, `--project=<name>`)
- E2E spec typecheck: `npm run typecheck:e2e`
- Linting: `npm run lint`

## Environment & Session Notes

- Node `^22.22.3`, `^24.15.0`, or `>=26.0.0` (Angular 22 requirement).
- Angular 22 runs this app zoneless and OnPush is the framework default (`@angular/core` `ChangeDetectionStrategy` docs: "OnPush is enabled by default"; `Default` is a deprecated alias of `Eager`) — never add explicit `changeDetection: OnPush` annotations; wanting the old check-always behavior would mean `Eager`.
- Dev-server ports: `npm start` serves on **4321** (pinned in `angular.json` → `projects.lore-stitch.architect.serve.options.port`); Playwright boots its own dev server on **4301** (`playwright.config.ts` `webServer`). Neither uses Angular's default 4200.
- Coverage thresholds (statements/functions/lines ≥ 80, branches ≥ 75) are enforced inside the test run — a threshold regression fails `npm test` itself. Pruning tests is coverage-sensitive: diff the per-file coverage table against the phase-start baseline before finishing — global thresholds stay green while a touched file drops, because a deleted duplicate assertion may still have held a unique execution path.
- Unit-test scoping: the runner is the vitest-backed `@angular/build:unit-test`, whose `ng test` positional is a **project name** (`lore-stitch`), never a spec path — an invalid positional derails argument parsing and the error misnames innocent flags (`ng test --watch=false src/app/features/about` dies with "Unknown argument: watch", not a word about the positional). Scope a debug run with `--filter=<regex on suite/test names>` (`npx ng test --filter=changelog`); `--include` directory globs narrow the app build itself and die on "No loader is configured for .html files". Coverage runs inside every test (`angular.json` pins `coverage: true`), so a scoped run always exits red on the global thresholds (5.95% lines vs the 80% floor, observed) — scoping is debug-time iteration only; every gate runs the full suite.
- Playwright filters by spec-name substring (`npx playwright test delimiters round-trip`); a large "skipped" count is by design — phone-pinned tests skip on desktop projects; the projects are `desktop-chrome`, `mobile-chrome` (Pixel 7 — layout viewport 412×839) and `mobile-safari` (iPhone 14 — layout viewport 390×664; the 844/915 figures are screen sizes): name projects, not viewport figures. A geometry pin that only holds above ~705px viewport height (e.g. a ~640px export menu clearing a 65px bottom bar) silently reds on the shorter device — give viewport-relative surfaces a fit cap (the `.export-menu` max-height precedent) instead of assuming the panel fits. Entry editor assertions must scope to the active tab body (`.mat-mdc-tab-body-active`) — inactive mat-tabs keep their inputs in the DOM. A "strict mode violation" failure means the locator resolved to several elements — scope it or pin the multiplicity with `.first()`; `test-results/<run>/error-context.md` lists what matched. Content that multiplies across releases (changelog sections, list rows) must never be pinned as unique.
- Playwright locator construction: `locator.filter({ has })` re-roots its inner locator — build the `has` locator from `page`, not the outer element (an outer-rooted inner locator can never match); `getByLabel` needs `{ exact: true }` when another control's label contains the text. Material tooltips also fire on long-press in touch projects (`touchGestures: 'auto'`), so hover-tooltip assertions are desktop-only — on touch projects assert the aria-label instead (`batch-and-tokens.spec` precedent).
- Zoneless e2e pacing: machine-speed UI event loops outrun the render flush — `EntryUpdatesService.addKey` reads through an `entry()` input that refreshes only on the next flush, so a fill+Enter loop drops keys (observed 2-of-6 landing). Pace input-driven sequences by asserting the rendered output grows before the next action (`addKeysToActiveEntry` waits out the chip-grid count).
- Playwright has no long-press primitive — synthesize it: on Chromium projects drive the real input pipeline via a CDP session (`newCDPSession` → `Input.dispatchTouchEvent` touchStart → hold past the threshold → touchEnd), which makes the engine synthesize the release click itself (a swallow-guard is provable); on WebKit dispatch cancelable DOM `PointerEvent`s with `pointerType: 'touch'` via `page.evaluate` onto the element and fire the release click manually (`el.click()`) — a dispatched pointerup never synthesizes one (`entry-list-selection.spec` precedent, verified on both mobile projects).
- Material Symbols render from a self-hosted pre-subsetted woff2 (`public/fonts/material-symbols-outlined.woff2`) built by `scripts/refresh-icons.mjs` scanning `src/`; after adding a new icon ligature run `npm run icons:refresh` or the ligature renders as raw text. Stage the regenerated font with the feature commit. The scanner's regex needs the literal `<mat-icon>name</mat-icon>` pair on one line — a newline inside either tag (e.g. a prettier-wrapped `</mat-icon⏎>`) silently drops the ligature from the subset; interpolated `{{ }}` names only land via the script's `DYNAMIC_ICONS`.
- Material chip theming from host classes must go through the `--mat-chip-*` tokens Material's internal rules read (e.g. `--mat-chip-elevated-container-color` for fills) — a literal `background:` on the host loses the cascade to `.mat-mdc-standard-chip` specificity.
- A component placed as a direct `mat-form-field` child matches no affix selector — `matTextSuffix`/`matIconSuffix` apply only to direct children, and anything else projects into the infix, rendering as a row docked inside the content well rather than beside it. A wrapped component's own container chrome (e.g. `mat-toolbar`'s `--mat-toolbar-container-*` tokens) must be neutralized through component tokens, never `::ng-deep`.
- Material checkbox activation ordering: `MatCheckbox` flips its state and emits `(change)` from the inner input's own target-phase click listener — a bubble-phase `preventDefault()` on the checkbox host runs too late to cancel the native toggle. Intercepting or swallowing a click on a Material control that owns its activation needs a delegated capture-phase listener on an ancestor (the entry-list range-selection interceptor precedent, Chromium-verified task 20).
- Material sidenav side-mode content margins: the editor pane's margin is host-bound to the container's `_contentMargins`, recomputed only by the public `MatSidenavContainer.updateContentMargins()` — which fires on drawer open/close animations, mode changes and window resizes, never on an inline width change. A shell that resizes a docked drawer must call it itself, and from an `afterRenderEffect`: a plain component `effect` runs before the template-binding phase writes `[style.width.px]`, so the call reads the previous width and locks in a one-step-stale margin (pointer drags mask it by re-firing per move; single-jump keyboard resizes end up wrong by the full delta — task 21's resizable drawer, probe-verified). Shell UI preferences such as the drawer width (`lorestitch.entries-drawer-width`, 320–480) persist via try/catch-guarded localStorage (ThemeService precedent), never `WorkspaceService`.
- Repo-wide prettier drift is pre-existing and `format:check` is not a maintained gate — format only the files you touch; a repo-wide format commit is a user decision, not a drive-by.
- Shared spec fixtures: unit specs reuse `src/testing/` (`projectOf`, `severityFixture`, `installMatchMediaStub`, and the PNG chunk builders in `png-fixtures.ts` — shared by unit and e2e card specs) and e2e specs reuse `e2e/helpers.ts` (`importLorebook`, `exportWorldInfo`, `selectFirstTwoRows`, `openExportMenu`, `exportCard`, `expectSnackbar`, `measureKeyStrip`, `addKeysToActiveEntry`) instead of copy-pasting helpers into each spec (root `TEST-REPORT.md` traces the duplication this removed). Committed e2e input files live in `e2e/fixtures/` (`defective-book.json` precedent) — `__screenshots__/` copies are working artifacts, never spec inputs.
- Task branches: every task executes on a `feature/<nn>-<slug>` branch created off `develop`; all of its phase commits land there. When the work completes, push the branch to origin and stop — never merge it back automatically. `git merge --ff-only` into `develop` happens only after the user has manually tested the branch and given the go.
- History is linear: merge with fast-forward only, no merge commits. Releases: `chore(release): vX.Y.Z` touching `package.json`, both `lore-stitch` version fields in `package-lock.json`, `CHANGELOG.md` (writer-facing voice), and the `version`/`updatedAt` fields of the `app:editor` entry in the byte-identical ARD twins `public/.well-known/{ai-catalog,ard}.json` — `updatedAt` is the release commit's UTC committer date (`YYYY-MM-DDTHH:MM:SSZ`, task 22 precedent), and nothing else in the tree flags the drift (caught a release stale on 2026-09-30) — plus an annotated git tag `vX.Y.Z` on the release commit, pushed with the branch.
- Check `git status --short` before each phase commit; unrelated local edits (e.g. `.gitignore`) may appear mid-session — keep them out of atomic phase commits.
- When a task changes pinned behavior — releases included — grep existing unit AND e2e specs for tests pinning the old behavior and migrate them within the changing phase (the About changelog test's release-specific pins are the precedent).
- Component-spec fake timers: `vi.useFakeTimers({ toFake: ['setTimeout', 'clearTimeout'] })` — the default set starves `fixture.whenStable()`; specs needing a real workspace settle first enable the faked pair after it and flush edit-idle windows through a `commitIdle()` helper (entry-editor section-spec precedent); settle debounces with `fixture.detectChanges()` then `advanceTimersByTimeAsync` (debounce-arming effects are view effects flushed by `appRef.tick()`). CDK's internal debounce runs on RxJS's interval-backed scheduler — a setTimeout-faked clock cannot settle it; use a real-timer ~10ms window for viewport flips (topbar.spec precedent).
- Responsive shape contracts: when one control renders different shapes per `LayoutService` band (e.g. a labeled pill above a breakpoint, an icon-only circle below), unit specs flip the shared match-media stub through every band the component branches on (`setMobile`/`setTablet`/`setDesktop` — the stub must answer every band query the service asks; two answered queries cannot classify the third band), and e2e assertions branch on the same boundary the component reads, not a neighboring one. Controls that must disappear in some app state are removed from the DOM (`@if`), never `display:none` — responsive specs count controls by accessible name, and hidden duplicates break the count (the history-drawer, GitHub-link and About buttons all follow this).
- ResizeObserver measurement in collapsible containers: a closed Material drawer collapses its children to 0×0, and skipping the zero-size delivery as invalid leaves a stale width in the signal — the reopen delivery then arrives as an equal-value `set` no-op that never re-runs the effect, freezing whatever fit ran while unmeasured (a `display:none` measurement row reads all-zero `offsetWidth`s, so the stale fit concludes everything fits; the row is not destroyed across the drawer cycle, so nothing re-materializes fresh). Store zero as an explicit unmeasured sentinel so close/reopen are real signal changes; keep the measurement row a hidden `width: max-content` strip rendering every candidate unconditionally (an absolutely-positioned box shrink-to-fits and under-reports), with a one-shot `document.fonts.ready` re-measure — the self-hosted font swaps in after first paint and changes metrics (task 21's `EntryKeys` whole-chip fit + `+N` counter precedent).
- Long gates kill subagent dispatches (~10-min inactivity timeout; full three-project Playwright runs take 7–20 min): brief qa agents to run Playwright per project (`npx playwright test --project=<name>`) and keep every single command under ~8 minutes, reporting between.
- A cancelled/killed subagent leaves uncommitted partial work: before re-dispatching, check `git status` + `git stash list` and prefer an audit-and-complete brief over a restart-from-scratch brief.
- Design-checkpoint mocks and screenshot captures drive the real app (`__screenshots__/*/[mock-]*.mjs` precedents): scoped SCSS does not follow a moved DOM node (`.batch-bar` styles live under `.list-header`); raw `mat-icon` elements need `class="mat-icon notranslate material-symbols-outlined"` to render the ligature font; Material hover tooltips race pointer moves during mat-select overlay picks and can stick visible mid-animation — suppress `.mat-mdc-tooltip-panel` capture-side; dismiss panes via their own close button (Escape is swallowed right after a select-overlay pick); accessible names drift across tasks — re-verify every label a capture waits on instead of copying an older script's labels verbatim (probe the DOM if unsure).
- The entries-drawer batch toolbar is at capacity at six 40px icon actions in the 320px drawer — the selection count rides a Material badge on a tri-state select-all icon button, and the drawer toolbar and mobile strip share that control contract: `role=checkbox`, tri-state `aria-checked`, count inside the accessible name (`selectFirstTwoRows` pins it). New batch actions join the ⋮ menu, never the row.
- Delimiters content contract: a trailing `---` reads as the old delimiter and is consumed by every style switch — the surviving scene-break protection is a `---` inside a tag/bracket payload with content after it. Preview and apply compose through the same `rewrapContent` path (preview-is-what-is-written); blank payloads are a no-op; payloads are byte-lossless.
- The dual-container DATA-token injections (the `inject(MAT_DIALOG_DATA) as X | null` pattern) are a deliberate shared idiom across the twin panes (`BatchOperationsDialog`, `DelimiterDialog`); change both twins together or neither.
- CDK overlays render through the native Popover top layer (`popover="manual"`): no body-level element can stack above an open menu at any z-index — anchor injected tooltips/helper nodes inside the open overlay pane. Related trap: Material tooltips never fire on truly `disabled` buttons — the disabled-with-explanation pattern is an enabled-but-muted row (`.card-export-unavailable` opacity recipe in `styles.scss`) with `matTooltip` + `aria-description` and a click-guard that snacks the same copy.
- No known pre-existing reds on `develop` — treat a red gate as your regression, not inherited noise (last two closed in task 17, 2026-09-27).
