# features/entry-list/

Sidebar entry list: quick filter, per-entry actions (add, duplicate, delete, drag-to-reorder synced with SillyTavern's display index), dirty badges, whole-chip key strips. `batch-operations-dialog` applies bulk patches (trigger strategy, insertion order set/shift, scan depth…) built by `batch-operations.model.ts`.

**Hints**

- The dialog is a dual-container pane (bottom sheet on phones) — open it via `ResponsiveOverlayService.openResponsive`.
- Batch actions have two surfaces (Task 06): the header toolbar renders on tablet/desktop only; on phones the docked bottom bar (shell `mobile-bottom-bar/`) swaps to these actions instead. The shell drives them through the narrow public API (`selectionCount`, `allFilteredSelected`/`someFilteredSelected`, `exportSelection`, `duplicateSelection`, `setSelectionEnabled`, `deleteSelection`, `clearSelection`, `selectAllShown`) — never by reaching into the selection signal.
- The text filter is debounced (`debouncedSignal` over the form query, `SEARCH_DEBOUNCE_MS`): the input and its clear button stay immediate, while the scan — and the `Entries N` badge and empty-state message, which read `filtered()` — settle ~200ms after the last keystroke. Tag chips keep filtering immediately (discrete taps). Matching runs over a per-entry haystack pre-folded once per entry change (`EntryListItem.search`, built by the identity-memoized `memoEntryHaystack`, which composes `entrySearchHaystack`), so each keystroke costs a plain `includes` scan. Virtual rows track by entry id (`trackById`), so a book-wide mutation re-renders only the changed rows.
- Range selection lives on the row checkbox only (Task 20): shift+click (desktop) or a `LONG_PRESS_MS` long-press (touch/pen) applies Gmail-style semantics over `filtered()` — the inclusive slice from the last plain-toggled anchor to the gesture row takes the gesture row's new state (`applyRangeSelection` in `entry-list.model.ts`), the anchor never moves on a range gesture, and a stale anchor (no anchor, filtered out, deleted) degrades to a plain toggle of the gesture row. Both gestures intercept the click capture-phase (`interceptCheckboxClick`) so MatCheckbox's native `(change)` toggle can't double-apply; a fired long-press swallows its release click the same way.
- Rows truncate, keys fold into a counter (Task 21): titles ellipsize with the duplicate/delete actions pinned at the row's edge (the row never scrolls horizontally), and each row's keys render through the per-row `EntryKeys` component (`entry-keys.ts`, host class `item-keys`) — whole chips, never compressed or ellipsized, with the ones that don't fit counted in a `+N` chip whose tooltip names them. The fit is measurement-driven (`fitKeyChips` in `entry-keys.model.ts`): a hidden `max-content` measurement row keeps every chip measurable, a `ResizeObserver` feeds the strip's live width (the shell's drawer is user-resizable), a zero-size delivery (the strip collapsed inside the closed phone drawer) is stored as the `null` unmeasured sentinel so a reopen re-arms the fit, and a one-shot `document.fonts.ready` re-measure catches the late font swap. The mobile-only close button emits `closeDrawer`; the shell binds it to `closeLeft()`.
